## Lessons Learned

- When new evidence surfaces mid-session that could plausibly widen the scope of an already-approved plan, explicitly re-confirm scope with the architect (via a direct question) before writing the new plan — don't silently inherit the old approved boundary just because it's the path of least resistion.
- A diagnostic log line placed immediately before a success-path return is structurally blind to every failure of that request — evidence-gap logging needs to wrap the failure path (try/except or middleware/exception-handler level), not sit right before the happy-path response.
- When a lifecycle hook that already had one async call gets a second async call added later (e.g. a second request added into an existing `useFocusEffect`), check the new call's query for missing indexes on its join/filter columns specifically — the commit introducing it is the most likely place for an unindexed access pattern to first appear, since it wasn't part of the original data-access design.
