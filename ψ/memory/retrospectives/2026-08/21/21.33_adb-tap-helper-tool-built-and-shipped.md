"never reuse a stale coordinate" rule from two sessions' worth of accumulated pain.

function had a leftover, broken fallback expression (`(TEXT_RE.search(node) or [None,

clean `.group(1) if match else ""` pattern before any testing began.

## Lessons Learned

- **A tool built specifically to fix a recurring bug pattern should be exercised
  against the real environment it targets before being declared done, not just
  read back for plausibility.** The value of `adb-tap` is entirely in whether it
  actually re-derives coordinates correctly against a live, changing UI — a code review
  alone couldn't have caught the XML-escaping edge case or confirmed `--clear` actually
  clears rather than appends.
- **When a planned test target turns out to be unusable (no logout screen, a
  cross-project tooling constraint, etc.), look for the most environment-independent
  substitute available rather than either forcing the original target or skipping
  verification.** Android's own Settings app served as a better test target here than
  either project's own screens, precisely because it doesn't depend on either app's
  auth state or Expo Go's SDK version.
- **Personal/cross-project tooling (a `~/bin` script, a shared helper) often lives
  outside any existing project's git repo — check for that explicitly before assuming
  "commit this" means "commit into the repo we're already in."** A repo-root check
  before staging anything would have surfaced the "not a git repo" fact one turn
  earlier here.
