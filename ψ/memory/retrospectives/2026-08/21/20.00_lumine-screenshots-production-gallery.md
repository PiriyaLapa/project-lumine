## Honest Feedback

Three friction points, all session-specific:

1. **Coordinate math after keyboard appearance was a recurring source of wasted round-trips.** The Android keyboard reflows the whole screen when it opens, so any field bounds captured before the keyboard was open become stale the moment it appears. I hit this twice (login screen, register screen) before consistently re-dumping the UI hierarchy after every keyboard-triggering tap rather than reusing earlier coordinates. This is worth internalizing as a hard rule for any future adb-automation work in this environment, not just a one-off gotcha.
2. **The stale-APK/no-Metro-server situation cost real time to diagnose** because the failure mode (a 401-shaped error message) looked exactly like a credentials problem, not an environment problem. Checking `ps aux` for a live bundler process earlier — before spending three rounds retyping credentials — would have shortcut the whole detour.
3. **Deploy verification hit the same "no working browser in this sandbox" wall noted in prior sessions' retros** (now a recurring pattern per the friction column), compounded this time by `piriyalapa.dev` being genuinely unreachable from this sandbox's network and the `*.vercel.app` URLs being behind Vercel SSO. `vercel inspect --logs` is a solid proxy for "did it build from the right commit," but it is not the same as looking at the rendered gallery, and I said so rather than implying I'd confirmed more than I had.

## Lessons Learned

- **When an app shows a specific, plausible-looking error (e.g. "Invalid credentials"), verify the request actually left the device before trusting the error message's framing.** Checking the receiving server's logs for a matching request (or its absence) disambiguates "wrong input" from "request never arrived" far faster than re-trying input variations. Generalizes to any client/server debugging session, not just this app.
- **On Android UI automation via adb, always re-derive tap coordinates from a fresh `uiautomator dump` after any action that could change the layout (keyboard open/close, screen transition, error banner appearing/disappearing) — never reuse coordinates captured under a different layout state.** Trust the accessibility tree's literal text content over a screenshot glance when verifying that typed input landed correctly; screenshots are for humans, the dump is ground truth for the automating agent.
- **A scope-limited local workaround (one DB row, one password reset) plus a properly filed upstream issue is the right shape of unblocking yourself when a real bug sits between you and a deliverable that isn't about fixing that bug** — don't silently patch application code to route around a bug discovered mid-task when the project's own rules require architect approval for that surface.
