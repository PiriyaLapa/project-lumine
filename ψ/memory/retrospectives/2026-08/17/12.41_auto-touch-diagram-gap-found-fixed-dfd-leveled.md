## Lessons Learned

- When a user finds one instance of "you verified narrowly instead of auditing the full surface" (e.g., one missing feature in a diagram set), treat it as a signal to re-scan the *entire* list you're already looking at for the same failure mode, not just fix the one instance reported — the other instances are usually sitting right next to the one that got caught.
- When hand-authoring structured markup (XML/JSON) incrementally across many `Edit` calls, validate after every few edits rather than only at the end — catches stray/malformed cells while the diff is still small enough to spot by eye, not just by a passing structural check.
- Editor lock/temp files (`.dtmp`, `.swp`, `~` backups) are a predictable side effect of opening a file in an external app for review — add them to `.gitignore` proactively once observed, rather than re-deciding "leave it untracked" every time `git status` is checked.
