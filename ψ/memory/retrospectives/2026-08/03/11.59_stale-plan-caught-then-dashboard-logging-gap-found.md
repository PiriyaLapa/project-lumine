## Lessons Learned

- **After any context compaction or long gap, treat the carried-forward summary as a hypothesis to verify against live repo state (branches, reflog, HEAD), not as ground truth** — especially for any plan file still marked "active," since a plan approved before the gap may already be fully shipped by work the current context never saw.
- **A concurrency guard that prevents a second racing call is a different fix from one that handles the first call failing** — verify both cases independently before considering a race-condition symptom fully resolved, especially when the exact same user-facing error text recurs after the guard ships.
- **When two root-cause theories for the same bug have already been investigated and falsified, the correct next artifact is often instrumentation (closing an evidence gap), not a third theory** — but resist the pull to state a plausible mechanism as fact in the process of proposing that instrumentation; re-derive whether the mechanism is even consistent with the code's actual error-branching logic before writing it down, even provisionally.
- **Knowing a lesson from memory and actually re-applying it under time pressure in the moment are different skills** — catching yourself mid-sentence by re-checking the code is more reliable than trusting that having read the lesson earlier in the session will prevent the same pull from recurring.
