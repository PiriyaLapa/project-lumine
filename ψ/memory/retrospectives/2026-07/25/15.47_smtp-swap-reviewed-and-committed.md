## Lessons Learned

- When a handoff or memory file states test counts, coverage percentages, or "verified" claims,
  re-run the verification yourself before acting on it rather than citing the stale number — memory
  is a point-in-time claim, not live state, and this generalizes far beyond this session (per the
  house rule already documented in `/recap`'s "Verify Before Reporting" section — this session is a
  concrete instance of that rule paying off, not a new rule).
- Before running any shell command whose failure could be path-relative (`cd x && ...`, relative
  `git add`), check `pwd` first if the working directory's history in the conversation is more than
  one or two tool calls old — cwd persists across Bash calls in this environment and silently
  drifts from what you last assumed.
