## Lessons Learned

- **When diagnosing "did my recent change break X," run the relevant `git diff` against the pre-change commit *first*, before asking the user multiple rounds of symptom questions.** A regression is either provably present in the diff or it isn't — that's often faster and more decisive than several rounds of human back-and-forth, and it narrows what's actually worth asking about afterward.
- **`AskUserQuestion` is for decisions with genuinely distinct options, not for open-ended data requests ("tell me the exact numbers you see").** Those belong in plain conversational text — reaching for the structured tool when there's only one real "option" produces a rejected call, not a shortcut.
- **A plausible diagnosis inferred from indirect evidence (code diff + workaround confirmation) is legitimate and often the best available under real constraints (no log access, no way to safely reproduce), but say so explicitly** — don't present "probably a cold-start race" with the same confidence as something confirmed from a stack trace.
