## Lessons Learned

- **When a sudo-gated install shows zero evidence of landing (no package, no files, sudo still uncached) after the user reports running it, don't ask for a retry — try the no-root alternative first.** Most dev tools (JRE, Node-based CLIs) have a portable/user-space install path; exhaust that before assuming an environment/session mismatch.
- **A single failed `npx <tool>` invocation is not proof the tool is unreachable — retry once before telling the user "I can't do this."** Registry/npx hiccups are transient; authentication state can also already exist from a prior session on the same machine.
- **In a WSL2-with-Windows-hosted-emulator setup, wrapper scripts that shell out to `adb.exe` are not equivalent to a real local ADB server** — they work for direct `adb shell`/`input`/`screencap` commands, but any tool making its own socket-level ADB connection (Maestro, Detox, etc.) needs either WSL2 mirrored networking or the Windows ADB server bound to all interfaces. This is a standing environment fact, not a one-off bug.
- **Before letting a task be marked "Done" in a workflow with a required side-artifact (evidence, approval, attachment), verify the UI still allows adding that artifact afterward.** If it doesn't, that's a real trap for users, not just a testing inconvenience — found this by walking into it myself.
- **When auditing "production readiness," cross-check the issue tracker against actual code/git state rather than trusting it.** Found two issues already resolved but still open, and one real un-tracked security gap (self-registration role selection) that no issue mentioned at all — trackers drift stale fast in a fast-moving solo project.
- **When screenshots and device control use different pixel scales, compute the raw coordinate explicitly (`displayed × scale_factor`) at the point of use, every time** — don't carry over a mental estimate from a previous tap in the same session.
