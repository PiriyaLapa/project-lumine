## Honest Feedback

Three friction points specific to this session, not generalized complaints:

1. **Two databases, one host shell.** The false "auth bug" alarm cost real time and, worse, cost Benz's trust for a few minutes on a finding that turned out to be nothing. The root friction was environmental: my Bash tool's shell and the actual Docker-networked backend don't share a `.env`, and nothing surfaced that mismatch until I went looking for it after the fact.

2. **Password-in-screenshot.** Designing a "don't relay the password through chat" safeguard and then partially defeating it with an un-guarded screenshot was a real gap in the workflow itself, not just a one-off slip — the screenshot tool doesn't know or care whether a field is masked.

3. **Metro/Expo reload cycles.** Every UI-visible change (card layout, new field) needed a manual bundle reload (`adb shell input text "rr"`, wait ~5-8s, screenshot, repeat) — this added up over many small iterations tonight and was pure overhead once the underlying pattern was well established.

## Lessons Learned

- Before drawing any conclusion from a diagnostic script against "the database," first confirm which actual database the *live service under test* connects to (check `docker ps`, `/proc/<pid>/environ`, or equivalent) — a host-level `.env` file is not proof of what a containerized process actually uses, and this gap is invisible until something disagrees.
- A "type the secret yourself, don't send it to me" safeguard is incomplete unless it also covers what happens *after* — screenshot/log capture tooling doesn't know a field is sensitive, so the safeguard must include confirming the field is masked before any capture, not just controlling who types it.
- When a written policy (a CLAUDE.md rule, a code comment) conflicts with what the shipped system actually does, checking the primary source directly (the real sample file, the actual running code) — not the config/mapping layer that's supposed to summarize it — is what surfaces the truth; the mapping/config layer can silently omit or drop information the source actually has.
