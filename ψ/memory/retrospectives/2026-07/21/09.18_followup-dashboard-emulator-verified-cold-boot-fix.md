## Honest Feedback

Three friction points, all mine to own:

1. **My own coordinate-scaling error** cost several wasted tap attempts on the Expo Go "Connect" button — I'd already internalized the 1.2x scaling rule earlier in the session but didn't apply it consistently when moving fast through a new UI flow. A checklist habit ("did I scale this coordinate?") before every `adb shell input tap` would have caught it immediately via the unchanged screenshot file size, which I did eventually notice but not right away.

2. **The Windows/WSL2 split** for the Android SDK (`ANDROID_HOME=/mnt/c/Users/.../Sdk`, `emulator.exe` on the Windows side, `adb` reachable from WSL2) wasn't discovered until I actually needed to cold-boot — `which emulator` had returned nothing earlier in the session and I'd moved on without investigating why. Worth checking `ANDROID_HOME`/`ANDROID_SDK_ROOT` up front in any WSL2 + Android Studio environment before assuming SDK tools are missing.

3. **A stale leftover process from before the cold boot** (an old Metro instance still holding port 8081) caused the very first post-reboot relaunch attempt to silently skip with no error the user or I would notice without reading the log closely — same class of "stray process from earlier state" issue flagged in the previous retro, but this time it was my own earlier process, not a different session's.

## Lessons Learned

- When a "warm" fix (relaunch, app reinstall) has already proven unreliable in one troubleshooting pass, escalate directly to the "coldest" available fix (full VM/emulator reboot) on the next pass rather than trying additional warm variations first — thoroughness of the fix should scale with how much warm-retry evidence has already accumulated, not reset to square one on each new attempt.
- In any WSL2 + Android Studio setup, check `ANDROID_HOME`/`ANDROID_SDK_ROOT` immediately if a Linux-side SDK binary (like `emulator`) is missing from `PATH` — the SDK and emulator process likely live on the Windows side (`/mnt/c/...`) and are invoked via WSL interop (`emulator.exe`), not installed natively in the Linux environment.
- When reading pixel coordinates off a screenshot to drive `adb shell input tap`, apply the display-to-device scaling factor as a fixed habit for every tap in a sequence, not just the first — an unchanged screenshot file size after a tap is a reliable, cheap signal that the tap missed and is worth checking before assuming a deeper failure.
- After restarting a long-running dev server following an environment reset (VM reboot, container recreate, etc.), explicitly check for and clear stray processes left over from *before* the reset, not just ones from other concurrent sessions — the reset itself doesn't guarantee old host-level processes are gone.
