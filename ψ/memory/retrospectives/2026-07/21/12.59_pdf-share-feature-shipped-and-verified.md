## Lessons Learned

- When you've written a lesson about escalating to a stronger fix after a specific failure pattern, check that lesson explicitly the next time the same symptom appears in the same session — don't re-diagnose from scratch and drift back into the weaker fixes the lesson was written to skip.
- Before using device rotation (or any orientation-dependent workaround) on a React Native/Expo app, check `app.json` for an `orientation` lock first — many production apps pin portrait-only, making rotation a guaranteed no-op.
- A header/action row that can silently overflow off-screen with no scroll affordance is worth flagging as a real UX bug the moment it's discovered, even mid-task on unrelated work — verify with `uiautomator dump` (or platform equivalent) to confirm it's genuinely unreachable, not just visually tight, before reporting it as broken rather than "just cramped."
- Don't treat a single successful fix (e.g. "cold boot solved it once") as proof of a deterministic solution to a flaky environment issue — hold it as "raised the odds," and be ready to escalate further (e.g. cold boot + reinstall) if it doesn't reproduce cleanly next time.
