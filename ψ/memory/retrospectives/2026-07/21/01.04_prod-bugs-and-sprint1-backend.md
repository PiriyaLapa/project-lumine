## Lessons Learned

- **`/health`-style endpoints that don't touch the DB are not sufficient liveness signals for diagnosing 500s** — always find and hit the *first* endpoint in the chain that actually queries the database before concluding "the service is up."
- **When a user explicitly stops a tool call twice with "wait for me to tell you how to proceed," that instruction outranks any automated completion-checker or goal-hook** — silence or elapsed turns is not consent; only an explicit go-ahead is.
- **Before testing "the account" in any multi-tenant system, verify identity fields (store_id, employee_code) against the specific record, not just "an account that logs in successfully"** — a working login is necessary but not sufficient evidence you're testing the right identity.
- **When a Docker container reports "healthy" but a dependent service can't reach it, check the container's actual network attachment (`docker inspect --format '{{json .NetworkSettings.Networks}}'`) before assuming the app-layer code is broken** — health checks can be stale relative to networking state.
- **Before implementing a multi-step backend feature plan, run parallel Explore agents to extract existing conventions (migration style, repo/service/router shape, test mocking patterns) and feed those verbatim into a Plan agent** — this reliably surfaces real schema gaps (missing columns, undefined state storage) that a single-pass read would miss, and gives the architect concrete decisions to make via `AskUserQuestion` instead of silently-invented defaults.
