## Honest Feedback

Three friction points, all environment/tooling, none of them about the actual feature code:

1. **Expo Go native bridge flakiness ate ~15 minutes.** `ClassCastException: host.exp.exponent.MainApplication cannot be cast to com.facebook.react.ReactApplication` on `UIManager` access, worked exactly once out of roughly eight cold-start/relaunch attempts, with no deterministic trigger I could isolate in the time spent. A dev-client/EAS build (matching how this project is actually versioned per CLAUDE.md) would likely have sidestepped this entirely.

2. **Docker port conflict with a pre-existing host `mysql.service`** cost a debug cycle in itself: my first attempt at overriding the compose port mapping used a plain YAML list override, which Compose v5 *merges* rather than replaces — both the conflicting `3306:3306` and my intended `3307:3306` ended up in the final config, and it still failed to bind. Needed the `!override` merge tag to actually force replacement. Not obvious from the compose docs at a glance.

3. **A concurrent, unrelated Claude Code session was already active in the same repo** (different session-id, polling via what looked like a "maw peek Lumine:Claude" loop per the dig-miner's cross-session read) and had left a stray Expo dev server running on the port I needed. I only found this by chasing `/proc/<pid>/fd` to locate its log file — there was no obvious surface signal that another session's process was involved until I dug for it.

## Lessons Learned

- Before reaching for a generic dev-client tool (Expo Go, a generic simulator, etc.) to verify a mobile feature, check the project's documented build/versioning convention first (e.g. an APK version table in CLAUDE.md) — if the team's actual workflow is installing built artifacts, the generic dev-client path may hit compatibility issues a proper build wouldn't, and that's wasted time discovered too late.
- Docker Compose (v2 spec, "Compose Spec" merge semantics) merges list-typed keys like `ports:` across `-f` files by default — it does not replace them. Use the `!override` YAML merge tag on the key when the intent is to fully replace a base value from an override file.
- Before starting any long-running dev server (Metro/Expo, uvicorn, etc.), check for already-running instances via `ps`/`ss`/`lsof` — including ones owned by other concurrent sessions, not just your own. A silent port conflict can look identical to "my command didn't do anything."
- When a UI feature's data dependency lives in a not-yet-applied migration on a shared/production-adjacent database, verify migration state (`alembic current`) before hitting the endpoint under test — never mutate shared infrastructure to make a test pass; surface it and let the architect choose the sandboxing strategy (this is exactly what happened here, and it was the right call).
- When an automated retry loop is genuinely stuck (not just slow), recognize the pattern explicitly (e.g. "1 success out of 8 attempts, no deterministic fix found") and hand a clear decision point back to the human rather than continuing to guess — and if a previously-scheduled fallback check fires *after* the human has already redirected you, treat it as stale and default to a passive/read-only response, not a resumption of the old plan.
