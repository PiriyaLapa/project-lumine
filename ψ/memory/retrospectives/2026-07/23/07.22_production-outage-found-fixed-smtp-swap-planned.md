## Lessons Learned

- Before merging into any branch that might be connected to auto-deploy, check what's actually configured to deploy from it — don't assume based on documented convention (`CLAUDE.md`'s "feat → develop → main" said nothing about which branch Render watches, and the two turned out to differ). If there's no cheap way to check directly, a quick unauthenticated-route probe (does a new-code-only endpoint 403 or 404?) is a zero-credential way to determine which version is actually live.
- When verifying authenticated production behavior without the real user's credentials, prefer in-process verification (call the real router/service function directly against the real DB, no network) for internal logic, or a freshly-registered, clearly-labeled throwaway account for anything that must prove the real HTTP/auth path end to end. Never fabricate a token for someone else's identity, even under direct instruction to "test the live endpoint" — there is consistently a safer equivalent that proves the same thing.
- A safety mechanism that's been coded but not yet deployed is not a safety mechanism — treat "built the gate" and "the gate is live" as two separate, independently-verifiable facts, and re-check the deployed state explicitly before reporting a protection as active, even in a session where you personally wrote the code.
